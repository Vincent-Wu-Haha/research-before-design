# Research Before Design

**先调研，再比较，最后给出能落地的方案。**

一个面向复杂方案设计的 Agent Skill。适合尚未选定路线的架构、技术选型、系统集成，以及有重要取舍的产品和业务方案。当前版本为 `v0.4.0`。

它先判断用户要研究方法、选择方案还是设计改造，再建立现状与决定性问题。第一轮寻找机制与真实替代，第二轮围绕可能改变判断的缺口深查原始证据和反证；不会把最新、最多 Star 或最多组件直接当作最好。

## 这个 Skill 改变什么

- **实际联网后再推荐**：先执行领域搜索、读取原始资料、比较候选，之后才给实质方案；不能先凭记忆定架构，再搜链接佐证。“赶时间”只缩小范围，不跳过取证。
- **主动发现主流方案**：先做不带预选品牌名的搜索，再核实代表产品/方法；通常覆盖 3–5 个现成方案及不同路线，相关候选较少时说明原因，不拿自建占位凑数。
- **比较真实替代路线**：包括成熟、近期、开源，以及适用时的学术路线；保留更简单或沿用现状的选项。
- **按机制比较升级路径**：先建立现状基线，按关键环节调查算法、专用模型、数据资源与实现，说明相对现状的增益，不只列知名框架。
- **核对指标可比性**：区分任务、数据集、实验设置和局部/端到端质量，分别回答技术进展与当前适合采用的路线。
- **让依据可追溯**：交付实际检索日期、查询方向、已读来源和候选取舍；核实版本、维护状态与许可，区分事实、推断和假设，主动找反证。不能仅凭搜索排名或 Star 宣称主流。
- **有选择地借鉴**：选一个主体方案，每个额外组件都需要收益、边界和成本依据。
- **按任务交付**：方法研究交付技术差异，选型交付取舍与验证，改造设计才展开迁移、成本和回退，不默认给每个问题套完整计划。
- **控制调研成本**：按决策风险调整深度；有停止条件，不为凑来源数量无限搜索。

简单修改和已确定方案的执行不触发完整调研。用户已选路线时，只研究未解决问题，不擅自推翻既定选择。

## 安装到 Codex

本仓库不需要运行服务器、安装 Python 依赖或配置新的 API Key。完整在线调研需要运行环境已有可用的搜索与页面读取能力；GitHub、论文工具按题目需要使用。

```bash
git clone https://github.com/Vincent-Wu-Haha/research-before-design.git
cd research-before-design
mkdir -p "${CODEX_HOME:-$HOME/.codex}/skills"
```

确认目标目录下没有同名 Skill，再复制整个文件夹，保留 references 和 agents：

```bash
cp -R skills/research-before-design "${CODEX_HOME:-$HOME/.codex}/skills/"
```

在新聊天中调用。其他兼容 Agent Skills 格式的环境可按其安装机制使用；本版包含 Codex 的界面元数据，未逐一验证其他宿主。

## 使用

```text
使用 $research-before-design，设计一个多来源数据同步方案。
当前没有选定路线，团队两人，四周做出第一版。
先调研主流、近期、开源方案和相关论文，再比较适配性、
开发/运维成本，推荐主体方案及可借鉴部分，给出分阶段落地计划。
```

也可直接描述复杂选型任务，让宿主自动匹配；自动匹配受宿主与模型影响，需要明确指定时使用 `$research-before-design`。

共同流程：识别任务 → 建立问题地图 → 实际联网发现主流候选 → 读取原始资料与反证 → 比较并检查证据 → 形成判断与最小验证。方法研究、方案选型、改造设计各有交付边界。

## 能力边界

Skill 是工作指令，不是搜索引擎或程序级拦截器，也不自动提供工具、账号或授权。工具不可用、原文受限或用户禁止联网时，明确标记调研未完成，整理约束、已有证据和待验证假设，不能伪装成已完成调研的最终设计。推荐的质量仍取决于可访问资料与实际验证。

本项目第一版不打包 MCP 服务、不实现爬虫、不自动运行候选项目。需要统一工具、托管研究资料或团队分发时，可以继续封装为 Plugin，复用此 Skill。
