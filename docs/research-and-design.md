# 第一版调研与设计记录

此文保留 v0.1.0 的历史决策。v0.3.0 将入口改为任务分流和证据循环；v0.4.0 增加实际联网、主流候选发现和设计前检查，参考文件保留方法研究、方案选型与改造设计。当前行为和边界以 [Skill 入口](../skills/research-before-design/SKILL.md) 为准。

调研日期：2026-11-03。以下是实际检索并读取的代表性来源，不是完整市场排名。项目状态随时间变化；未做各研究引擎的安装、性能或成本基准测试。

## 用户目标

复杂问题尚无方案时，先在网上寻找主流、最新、开源、GitHub 和论文路线，再逐项分析。推荐应吸收各家之长，同时考虑工作量、现有约束和实施可行性。

第一版采用独立 Skill，复用宿主已有工具，保持以后封装 Plugin 的可能性。覆盖技术方案，也支持有重要取舍的产品/业务方案；搜索来源和评价维度随领域调整。

## 实现路线比较

以下成本是本项目的设计判断，非第三方测量。

| 路线 | 当前适配性 | 一次性工作与持续负担 | 决定 |
| --- | --- | --- | --- |
| 独立 Skill + 已有搜索/读取工具 | 直接覆盖用户要固化的行为 | 编写指令、验证场景；后续维护工作流，无新增服务运维 | 第一版采用 |
| 把 GPT Researcher 等研究引擎作为运行时依赖 | 适合需要独立自动研究服务、批量报告的场景 | 增加运行环境、模型/检索配置、调用成本和升级维护；未实测 | 当前不引入，借鉴研究流程 |
| 自建 MCP Plugin + Skill | 适合统一新工具、连接服务及分发 | 工具、鉴权、部署和维护视实现而增加；仅打包 Skill 则较轻 | 待出现真实工具/分发需求后评估 |

不做固定搜索引擎集成，不实现自动评分器，不要求多 Agent。以上能力如有真实需求可以增补，但会增加依赖与维护，不是流程正确的前提。

## 第一版设计

Skill 入口保存触发边界和必要规则；两个渐进读取的参考文件承载搜索方法与交付结构。界面元数据保留自动匹配，并提供显式调用提示。

步骤：明确决策 → 搜索并读原始资料 → 按硬约束筛选并比较 → 选择主体与有依据的借鉴 → 给落地计划 → 按证据充分度停止。

关键设计取舍：

- “先调研”不禁止理解需求或形成搜索方向，禁止的是在取证前锁定实质方案。
- 主流、近期、开源、论文是搜索覆盖方向，不是每次都要凑齐的报告栏目。无关或缺失必须说明。
- 不规定最低来源数量或默认大规模并行；补查围绕可能改变选型的缺口展开。
- 先硬约束后比较；定性判断优先于没有依据的精确分数。
- 选主体后借鉴。组合的兼容、故障边界和维护成本也是选型对象。
- 工作量要求区间、前提与单位，未知项不能被包装成零成本。
- 无法联网不伪造研究，也不必完全停工；可继续做约束整理与验证设计。
- 不自动写入私人资料库或安装到个人 Skill 目录，公开仓库不包含用户内部系统信息。

## 迭代与验收

基线响应中，Agent 在没有证据时仍可能首先提出熟悉的队列架构，即使随后承认为初步建议。因基线没有联网，不能由此断言 Agent 在有搜索工具时也会跳过搜索。针对这一风险，第一版明确区分“问题拆解”与“实质性推荐”。

行为场景覆盖无网、赶时间、组合过度、已有路线、简单任务和来源可信度；另有一个真实联网的路线比较示例。验证记录见 [results-v0.1.md](../evals/results-v0.1.md)。这些检查是冒烟评估，不构成稳定性或通用正确性的证明。
