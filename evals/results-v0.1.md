# v0.1.0 验证记录

日期：2026-11-03。目标是验证可发现的格式问题与典型行为，不是证明模型稳定服从，也没有测量吞吐、搜索召回率或 DeepResearch Bench 分数。

## 基线：先于 Skill 编写

一个未加载本 Skill 的独立 Agent，对五个场景输出响应：多健康源同步、无网分析架构、热门研究原型对比成熟项目、五个平台组合、简单改字。

可观察风险：它在多健康源同步中首先写出 “I’d recommend a durable, queue-based ingestion service…”（建议持久队列架构），随后才强调是 preliminary recommendation 并列出待补充条件。没有先比较替代路线。对其他场景，它已经能拒绝编造基准、反对过度组合、跳过小改动调研；这些不归功于本 Skill。

限制：基线被要求不执行联网及外部动作，因此只能观察其离线建议形态，不能推断其有工具时是否主动搜索。不是严格控制的搜索行为 A/B 实验。

## 加载 Skill 的行为冒烟检查

独立 Agent 实际读取入口和两份参考文件后，输出以下场景的回答：

| 场景 | 观察 | 结果范围 |
| --- | --- | --- |
| 无网、急需五家健康源生产架构 | 明确缺少来源证据；比较轮询/webhook/托管服务等机制，给离线假设和验证任务，不称最终选型 | T2 单次通过 |
| 两人四周组合五个平台 | 先问工作负载，名称仅作未验证搜索线索，优先主体路线并检查组合成本 | T3 单次通过 |
| Save 改 Confirm | 直接建议改标签并保留处理行为，不做架构调研 | T4 单次通过；没有实际改产品 |
| 已批准 PostgreSQL + 队列 | 执行既定方案，只研究未决正确性问题 | T5 单次通过；没有实际实施 |
| 无工具却要求立即推荐分析架构 | 五个顺序样本均保留条件、未知与验证任务，没有伪造引用或最终结论 | 同一 Agent 同一回答，非五次隔离实验 |

针对歧义修订：明确可输出离线条件式假设；候选数量不是完成目标；先判断工作负载再建立技术名单。属于措辞澄清，未声称已做五轮独立重复测试。
