# v0.3.0 验证记录

日期：2026-11-04。目标是检查任务分流、证据边界与交付范围；不是联网研究质量、稳定服从率或性能提升的证明。

## 本次变更依据

此前实际使用中，方法升级问询退化成知名框架罗列，并过早推荐接入路线。v0.2.0 已补充机制比较，但入口仍默认推进选型和实施计划。此次用任务分流、最小问题地图、两轮研究及证据链重组流程，不再要求所有问题交付完整改造计划。

## 可复用提示与合成资料

两名独立 Agent 分别读取 v0.2.0 和 v0.3.0 入口及必要参考，使用相同提示，不继承主对话。指令：只读、不联网、不修改文件；这是合成资料包，不代表现实项目；分别实际回答 A/B/C，每条最多 350 字，最后列出遇到的指令歧义。

- **A 方法研究**：“我们用 OldExtract，想知道有哪些更先进方法，先别给迁移计划。”用户说用 2022 版但没有上游代码。合成原始论文 P1：专用 NER 在 D1 实体识别 F1=.93，通用 LLM 在 D2 关系抽取 F1=.79；工具库 P2 支持受约束 JSON 输出，未评估语义准确率；实体链接 P3 在 D3 用候选检索和上下文重排优于单候选链接。
- **B 方案选型**：“两个人两周，必须离线、禁止外传。应该选本地 A 还是云端 B？”A 离线可用、许可允许，目标域质量未测；B 供应商榜单更高，但必须上传文本；已有 OldExtract 可离线。
- **C 改造设计**：“已决定本地 A，帮我设计迁移，别重选。”已有输出契约 v1，A 返回 v2 结构；历史数据须保留，可离线试跑；吞吐和回滚耗时未知。
