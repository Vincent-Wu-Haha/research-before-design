# 一人一天内，如何复用“先调研再设计”

建议以独立 Skill 为主体，借用 GPT Researcher 的问题拆分与来源追踪思路，暂不接入其运行时或自建 MCP。信心中等：这符合当前约束，但尚未验证跨任务稳定性。

口径：一名熟悉 agent 的开发者，已有可用搜索、网页读取与文件能力；假设每周两次选型，每次比较三条路线、读取三至六份一手资料、输出千字报告。不新增托管服务、不申请付费 API，一天交付首版。研究截至 2026-11-03；不涉及模型算法创新，因此未另查论文。

| 路线 | 依据、适配与代价 | 本人估算：首次／每月维护 |
| --- | --- | --- |
| 独立 Skill | 官方支持指令与参考文件按需加载，可显式调用；适合复用已有工具。[1] 无新增进程，但无法硬性保证每次都执行步骤；隐式触发也可能遗漏。 | 3–6 人时／0.5–1.5 人时 |
| GPT Researcher 运行时 | 提供问题规划、抓取、来源追踪与汇总；Python 包可独立调用，无须部署网页服务。[2] 默认接入模型与搜索密钥；Ollama 是替代路径，但需本地运行条件，官方提示部分其他模型会有上下文或响应问题。[3] 现有 agent 的工具能否直接复用，未知。 | 6–16 人时／1–3 人时；若模型或适配器未就绪，超过一天 |
| 自定义 MCP 插件 | MCP 可提供工具、资源和提示，本地 stdio 无须托管。[4] 适合需跨客户端调用、结构校验的能力；本题主要缺流程约束，协议本身不保证研究质量。需维护进程、工具参数和客户端配置；不能假定服务端能直接调用宿主搜索。 | 8–20 人时／1–3 人时；包含最小接线与错误处理 |

这些是本人按编写、接线、试跑和修订拆分的工程估算，非实测工时；一人日按八小时，日历时间另受环境等待影响。三条路线都消耗现有 agent 配额。Skill 预计新增现金支出为零；MCP 本地进程仍有机器与维护成本；GPT Researcher 的模型、搜索、重试用量未知，不能把开源等同免费。未确认可用端点前，其默认接线不满足本次预算约束，也不能断言所有配置都必须付费。

首版只需 Skill、比较方法和交付模板。借鉴 [2] 的“问题→证据→汇总”，在现有工具间传递 URL、读取日期、主张与缺口，落为 Markdown；这是一种流程设计推断，不引入代码依赖或继承对方许可。GPT Researcher 仓库标示 Apache-2.0；本轮不复制代码。[2] 维护责任由开发者承担：工具失败时换已有工具，仍失败就交付待验证项。

当天安排：1–2 小时完善边界与模板，1–2 小时跑两道真实题，1–2 小时抽查引用并修订。拟定验收：比较所有有实质差异且可行的路线，数量随约束调整，决定性事实均可回到实际读取的原文；包含反证、带前提的成本和回退条件。若连续两次漏关键证据，先修订显式检查与提示；只有出现跨客户端复用或机器可校验输出的实际需求，再试 MCP。需要大量自动并行研究且端点已就绪时，重评 GPT Researcher。

本次已实际搜索并读取四份官方资料。Exa 读取遇额度限制后，改用现有网页工具成功取证；未安装或启动任何候选。这个流程在本题可用，不能据此宣称生产可靠。只查官方材料，无独立质量基准；仓库 main 与滚动文档未锁定版本，未核实最新发布号，维护质量与真实运行成本仍未知，现有证据不支持比较报告准确率。证据已足以判断一天内的集成负担，故停止扩搜。
